# Worker 파일 읽기 성능 측정

## 변경

매 작업의 실행 대상 확인은 프로젝트 전체를 다시 발견하고 실제 경로를
확인한다. 이때 도구 실행에 사용하지 않는 각 프로젝트의 Git 브랜치와 변경
상태까지 조회하던 비용을 제거했다.

`scanWorkspace`의 `includeGitMetadata` 기본값은 기존 동작을 유지한다.
Worker의 작업 직전 검증에서만 이 옵션을 끈다. 시작 시와 heartbeat에서는
전체 메타데이터를 조회하고, `project_status` 같은 명시적 상태 도구는
자체적으로 현재 Git 상태를 조회한다.

프로젝트 발견, marker·ID·별칭·중첩 프로젝트·개발 runtime-self 처리,
실제 경로 확인, 실행 대상 비교와 잠금은 생략하거나 캐시하지 않는다.

## 측정 조건

```sh
npm run build
node scripts/benchmark-worker-reads.mjs
```

- Windows x64, Node v24.19.0.
- 1·8·24개의 실제 임시 Git 저장소. 저장소마다 package marker와 작은 읽기
  파일이 있다. 준비용 Git 작업은 측정에서 제외한다.
- 각 경우에 준비 호출 3회 후 15회를 측정했다.
- Worker 수치는 poll로 작업을 받은 시점부터 결과 제출까지다. 실제 worker,
  filesystem과 Git을 사용하지만 HTTP 전송은 메모리 응답으로 대체한다.
- 로컬 MCP 수치는 실제 SDK의 메모리 transport를 통한 도구 호출이다.
- 전후에 같은 계측 스크립트를 사용했다. 파일 접근과 Git 호출을 그대로
  실행하면서 횟수를 센다. 실제 ChatGPT·인터넷·OCI 왕복 지연은 포함하지 않는다.

## 기록된 전후 결과

단위는 ms다. p50은 중앙값, p95는 15개 표본의 상위 지연값이다.

| 경로 | Git 프로젝트 수 | 이전 p50 | 이후 p50 | 이전 p95 | 이후 p95 | 읽기당 scanner Git 호출 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Worker 파일 읽기 | 1 | 74.77 | 14.23 | 83.94 | 213.40 | 2 → 0 |
| Worker 파일 읽기 | 8 | 566.47 | 19.12 | 844.37 | 41.37 | 16 → 0 |
| Worker 파일 읽기 | 24 | 1694.89 | 72.88 | 2091.06 | 357.27 | 48 → 0 |
| 로컬 MCP 파일 읽기 | 1 | 19.46 | 30.05 | 24.90 | 182.58 | 0 → 0 |
| 로컬 MCP 파일 읽기 | 8 | 18.70 | 24.26 | 24.40 | 42.40 | 0 → 0 |
| 로컬 MCP 파일 읽기 | 24 | 15.43 | 28.96 | 18.78 | 144.87 | 0 → 0 |

Worker의 나머지 filesystem 호출 수는 전후 동일했다. 예를 들어 24개
프로젝트에서는 `realpath` 29회, `stat` 25회, `readdir` 26회, `access`
224회, `readFile` 26회, `lstat` 3회다.

수정하지 않은 로컬 MCP 대조 경로에서도 지연 변동이 컸고, 1개 프로젝트의
worker p95는 오히려 증가했다. 이 한 번의 측정으로 꼬리 지연이나 모든
사용 환경의 개선을 주장하지 않는다. 확정한 개선은 작업 검증에서 불필요한
Git 조회를 없앤 것이며, 재현 조건에서 worker 중앙값이 줄었다.

## 회귀 검증

`src/workspace/registry-performance.test.ts`는 다음을 확인한다.

- Git 메타데이터를 끈 발견 작업에서 실제 Git subprocess 호출이 0회다.
- 기본 scanner의 Git 메타데이터는 유지되고, 두 모드의 프로젝트 발견 결과는
  Git 필드와 관측 시각을 제외하면 같다.
- 중첩 프로젝트와 runtime-self의 ID 충돌 처리도 같다.
- 실제 worker loop의 파일 읽기는 Git 조회 없이 내용·해시를 반환한다.
- 작업 후 heartbeat와 명시적 프로젝트 상태 조회에는 현재 Git 정보가 있다.

기존 worker의 marker 제거·경로 변경·인스턴스 불일치 차단 테스트도 함께
검사한다. 로컬 MCP의 반복 상태 읽기나 저장 직렬화에는 이번 최적화를
적용하지 않았다.
